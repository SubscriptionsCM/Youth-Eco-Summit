# Admin registration spreadsheet download

Administrators and the owner can select **Download registrations (.xlsx)** on the admin Overview or Forms & submissions page (`/admin/reference-forms#registration-download`). Each click prepares a fresh workbook with Overview, Students, Educators, School registrations and School directory tabs. It includes all years, including imported historical forms. Inbox filters do not affect this explicitly labelled full export. Drafts, competition entries, unclassified forms, secret controls, verification codes and passwords are excluded.

The workbook retains original submission timestamps, India reporting times, original visible registration fields, textual phone numbers, school IDs and postal codes. The directory is a separate list of non-trashed, non-purging school branches, including active, pending and inactive branches. Registration totals count completed forms, not unique people. Spreadsheet strings remain literal strings, including user input beginning with formula characters.

The existing protected export endpoint handles `GET /api/admin/exports?resource=registrations&format=xlsx`. It checks the current active administrator/owner account before reading data and again before delivery. A repeatable-read, read-only transaction captures the snapshot. Successful exports record counts and the snapshot time in the activity log. The response is a private, non-cacheable Excel attachment. No workbook is stored on the public server. The UI prevents duplicate concurrent downloads, reports errors, cancels pending requests when unmounted and releases its private browser object URL.

This change starts from the current deployed deadline release, `d9a4fa82a4795dde0b0894eb8c0aa1e2b87c60f3`. It adds the export module, reusable download component, two admin placements and focused tests. There are no database migrations, dependency changes, public-site changes, imports, seeds, data restores or worker changes. Keep the current runtime environment, private uploads and mail configuration.

Validation: the production build (including TypeScript) and 59 focused tests passed. Tests cover current/historical classification, secret exclusion, literal spreadsheet strings, original times, leading zeroes, owner/admin authorization, permission revocation during generation, an export larger than an inbox page, manual school names, empty workbooks, download/error handling, existing inbox behavior and the deadline setting. An independent read-only code review found no P1/P2 issues. Chromium downloaded and read the workbook from the exact assembled artifact using an isolated PostgreSQL fixture, checked an export from a filtered inbox, verified 360 px layout, simulated a retryable server failure, confirmed the deadline setting and denied anonymous access. The isolated fixture never used production data or notifications.

A read-only production record check found 367 completed registration forms (197 student, 86 educator and 84 school forms), 138 directory branches and 349 incomplete forms excluded at verification time on 23 November 2026. These are a snapshot, not fixed export limits. New registrations are included automatically on the next download.
