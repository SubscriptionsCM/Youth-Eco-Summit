# Admins can invite other Admins

Every active Admin can now choose **Admin** or **Judge** in **Staff accounts → Send staff invitation**. The recipient receives the existing private invitation link and sets their own password. This updates invitation issuance, token setup and transactional token consumption consistently. Inactive or demoted inviters cannot complete a pending invitation. The accepted role, contact and optional username come from the stored invitation, not the acceptance request. Owner invitations and privileged-account management keep their existing Owner restrictions.

The change starts from the latest deployed `a70e6630438dd822d030dd59495556e81e76e1bf` release. It changes only the invitation role option and three matching server permission checks, plus tests and documentation. It preserves the Forms & submissions-only registration download, editable deadline, native authentication, current homepage/video, private uploads, database and email transport. No migration, seed, bootstrap, import or data restore runs.

Release: `/srv/youth-eco-summit/releases/20261123-admin-invites/runtime`. The immediately preceding current release remains `/srv/youth-eco-summit/releases/20261123-registration-download-forms-only/runtime`. Existing static browser chunks and public assets are preserved byte for byte; conflicting new generated assets receive an `admin-invite-` prefix with corresponding references in the new artifact. The worker is unchanged. Rollback switches only the web artifact; it must not restore the pre-change database backup, because an explicitly requested account removal occurred during this maintenance task.

The production build (including TypeScript) and 69 focused tests passed. Tests cover Admin/Owner invitations, accepted account roles, sign-in, token-bound contact/username, password validation, expired/consumed tokens, issuer deactivation/demotion, rechecking authority after token lookup, Judge/participant restrictions, existing account management and current download placement. An independent read-only review found no P1/P2 issues. Chromium tested the exact assembled artifact against an isolated PostgreSQL database and a local mail-capture script: an Admin selected Admin and sent an invitation through the actual form, the recipient completed setup and acceptance, signed in, and invited another Admin. Owner and Judge restrictions and Forms-only download placement were verified. No production users were created and no real invitations were sent during verification.
