# Youth Eco Summit live WordPress deployment

Deployed on 6 October 2026 to https://youthecosummit.com/. The existing Hostinger installation runs WordPress 6.9.9 and PHP 8.1.34, without a Node.js runtime. This deployment uses the latest public Next.js frontend as a WordPress theme and keeps WordPress as the temporary registration backend.

## Active components

- Theme: `wordpress/yes-frontend-theme/`, generated by `npm run build:wordpress-frontend`.
- Plugin: `wordpress/yes-native-portal/` (1.0.5), providing native forms, saved steps, the school-name directory and frontend REST responses.
- Existing Forminator registrations remain in use: student 48441, teacher 48437, school 9188, partner 9213, school nomination 8916.
- Existing Ultimate Member login form 12418 and WordPress accounts remain in use. miniOrange remains responsible for the site's existing OTP integration. Provider delivery has not been tested with real phone numbers or email addresses.
- Public Next.js assets are served from `/_next/static/`, `/images/` and `/documents/`. The theme can also serve its bundled assets if the root copies are unavailable.
- Native form pages load only the required form/account assets; they do not hydrate the exported React form components. Ultimate Member assets load only on account/login routes, avoiding duplicate Select2 libraries.

The school form has four steps: School, Location, Contact and Review. Student registration has a required Class 5–12 field. The teacher form lists all ten 2027 competition formats. Existing notification settings, registration consent and Subscriber account roles were preserved. Student and teacher accounts use the password entered into the existing `password-1` field; the old `auto` mapping ignored that visible field and generated a different password.

The WordPress export's live status labels refer to student registration only. They do not claim that competition uploads are enabled. The original Next.js/PostgreSQL source and approved competition deadline remain unchanged.

## Saved forms and dates

Forminator saves drafts through its existing AJAX handler. The portal saves after valid step changes and provides a private resume link. Passwords, uploads, verification codes and consent are excluded from autosave and must be supplied again. No answers are stored in browser local storage. Native pages suppress analytics and send a `no-referrer` policy to protect private draft tokens.

Forminator 1.53.1 originally used `draft_id VARCHAR(12)`. The deployment extends that column to nullable `VARCHAR(64)`, preserving existing rows and indexes. New resume tokens have 48 hexadecimal characters. The plugin checks this migration during activation and explicit form preparation, rather than changing the schema on public requests. Future Forminator updates must preserve this column capacity; rerun `yes_native_ensure_draft_schema()` if a plugin migration changes it.

miniOrange's Forminator validation originally rejected draft saves for unverified phone numbers. The portal skips that exact OTP callback only during Forminator's nonce-validated draft-saving hook for the configured forms. Final registration still requires OTP. Server-side draft validation checks form ownership of an existing token and verifies that the token was actually persisted before returning a successful save response.

Student registrations and competition entries close on **5 November 2026 at 11:59 p.m. IST**, using the exclusive UTC boundary `2026-11-05T18:30:00Z`. School and teacher registrations remain available. The public countdown uses **29 January 2027**.

## Scope still pending

The ten 2027 competition entry forms are prepared as **draft posts**, with public final submission disabled. Before publishing them, complete the remaining guardian/publication consent, real school-ID mapping, team eligibility policy, and authoritative file checks for word counts, duration, orientation and other category requirements. Do not enable them merely by setting `entries_enabled`.

Existing school dropdowns contain name strings, duplicate names and no verified permanent IDs. The directory identifies this limitation and does not invent EDU IDs or merge branches. The WordPress account page and Forminator staff tools are available; the full Next.js school dashboard, PostgreSQL records and private object-storage submission pipeline have **not** been migrated to WordPress.

The standalone `yes-participation-bridge` plugin and `docs/wordpress-temporary.md` describe an earlier alternative that redirects to a hosted Next.js portal. That bridge is not the active live architecture.
